Streaming Responses

For long answers, waiting for the whole response feels slow even when it isn't. Streaming renders text as it's generated. You'll build the Helios SRE Live Postmortem Writer — it streams a structured incident report and measures time-to-first-token (TTFT), the metric that drives perceived latency.

Streaming vs. buffered

run() vs. run_stream()

run() returns once, fully formed. run_stream() yields incremental chunks as the model produces them.

Iterate the stream

run_stream(...) is an async generator. Iterate it with async for; each update.text is an incremental piece.

stream chunks
print("Agent: ", end="", flush=True)
async for update in agent.run_stream(prompt, thread=thread):
    if update.text:
        print(update.text, end="", flush=True)
💡
flush=True matters
Terminals line-buffer by default, which defeats streaming. print(..., end="", flush=True) forces each chunk to the screen the moment it arrives.

Measure time-to-first-token

TTFT — how long until the first visible character — is what users perceive as "responsiveness". Capture it by timing the first non-empty chunk.

  1. Start a timer before the loop.
  2. On the first chunk with text, record perf_counter() - started.
  3. Keep accumulating chunks for the full text and final metrics.
measure TTFT
import time

started = time.perf_counter()
ttft = None
chunks = []
async for update in agent.run_stream(prompt, thread=thread):
    if update.text:
        if ttft is None:
            ttft = time.perf_counter() - started
        chunks.append(update.text)
        print(update.text, end="", flush=True)
full = "".join(chunks)
print(f"\n[streamed {len(full)} chars · TTFT {ttft * 1000:.0f} ms]")

Streaming is a UX and a cost lever
Beyond feel, streaming lets you render partial results, cancel early if the answer goes off-track, and surface progress in long agentic runs. Pair it with thread memory and you get responsive, stateful experiences — the foundation for the chat and workflow UIs you'll build later.
