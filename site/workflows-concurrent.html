Concurrent Workflows

When subtasks are independent, running them one after another just wastes wall-clock time. A concurrent workflow fans out to multiple agents in parallel, then merges their results. You'll build the Lumen market brief: three analysts — fundamentals, technicals, and sentiment — work at the same time, and an aggregator synthesizes one brief.

All three analysts run simultaneously; the aggregator waits for all of them, then composes the final answer.

1 · Build the parallel analysts

main.py
import asyncio
from agent_framework import ConcurrentBuilder
from agent_framework.azure import AzureOpenAIChatClient


async def main() -> None:
    client = AzureOpenAIChatClient()

    fundamentals = client.create_agent(
        name="Fundamentals",
        instructions="Assess revenue, margins, and valuation. 4 bullet points.",
    )
    technicals = client.create_agent(
        name="Technicals",
        instructions="Assess price trend, support/resistance, momentum. 4 bullets.",
    )
    sentiment = client.create_agent(
        name="Sentiment",
        instructions="Summarize recent news and analyst tone. 4 bullet points.",
    )

2 · Fan out with ConcurrentBuilder

Pass the participants — they run in parallel. The default aggregator concatenates their outputs; supply your own with .with_aggregator(fn) to synthesize instead of stack.

main.py (cont.)
    async def synthesize(results: list[str]) -> str:
        joined = "\n\n".join(results)
        writer = client.create_agent(
            name="Brief-Writer",
            instructions="Merge the analyst notes into one tight market brief.",
        )
        resp = await writer.run(f"Analyst notes:\n{joined}")
        return resp.text

    workflow = (
        ConcurrentBuilder(participants=[fundamentals, technicals, sentiment])
        .with_aggregator(synthesize)
        .build()
    )

    result = await workflow.run("Analyze ACME Corp for a swing-trade horizon.")
    for output in result.get_outputs():
        print(output)


if __name__ == "__main__":
    asyncio.run(main())

Why parallel matters

  1. Latency — three 4-second analysts finish in ~4s parallel vs. ~12s sequential.
  2. Independence — sentiment doesn't need fundamentals' output, so don't make it wait.
  3. Diverse perspectives — the aggregator gets genuinely independent takes, not a chain where later agents anchor on earlier ones.
💡
Default vs. custom aggregator
Skip .with_aggregator(...) and you get all outputs concatenated — perfect when you want every analyst's raw view. Add an aggregator agent when you need one synthesized answer.
🏢
Map-reduce for agents
Concurrent workflows are the agent version of scatter-gather: classify a document against ten policies at once, score a candidate on five rubrics, or poll multiple data sources in parallel. You've now seen all three core shapes — sequential, handoff, and concurrent — the building blocks for the multi-agent systems in the architecture track.
