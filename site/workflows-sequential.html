Sequential Workflows

One agent doing five jobs is a jack of all trades. A sequential workflow chains specialists — each agent's output becomes the next one's input. You'll build the Quill content pipeline: a Drafter writes, an Editor tightens, and an SEO Packager ships — a publishing assembly line.

Each stage sees everything before it, so the editor edits the draft and the packager packages the edited version.

1 · Build the specialists

Three agents from one shared client — each with a tightly scoped instruction.

main.py
import asyncio
from agent_framework import SequentialBuilder
from agent_framework.azure import AzureOpenAIChatClient


async def main() -> None:
    client = AzureOpenAIChatClient()

    drafter = client.create_agent(
        name="Drafter",
        instructions=(
            "You are a content writer. Write a focused 3-paragraph blog post "
            "from the given brief. Engaging, concrete, no filler."
        ),
    )

    editor = client.create_agent(
        name="Editor",
        instructions=(
            "You are a line editor. Tighten the draft for clarity and tone, "
            "remove redundancy, and fix any weak claims. Return the improved post."
        ),
    )

    packager = client.create_agent(
        name="SEO-Packager",
        instructions=(
            "You are an SEO packager. Add a compelling title, a 155-char meta "
            "description, and 5 tags. Output the final publish-ready document."
        ),
    )

2 · Wire them with SequentialBuilder

Pass the participants in order. build() returns a Workflow you run like anything else; get_outputs() returns the final stage's output.

main.py (cont.)
    workflow = SequentialBuilder(
        participants=[drafter, editor, packager],
    ).build()

    result = await workflow.run(
        "Write a post: why platform teams should publish internal MCP servers."
    )

    for output in result.get_outputs():
        print(output)


if __name__ == "__main__":
    asyncio.run(main())
💡
Stream the pipeline
Pass stream=True to workflow.run(...) and iterate events to watch each stage produce output live — great for long pipelines where you want progress, not a long silence.

# Ship Tools, Not Tickets: Why Platform Teams Should Publish MCP Servers

**Meta:** Stop rebuilding the same integrations. Publish internal MCP servers
so every agent in your org can reuse vetted tools through one URL.

When every team wires its own integrations, you get five slightly different
payment clients and zero shared governance. Publishing an internal MCP server
flips that: the platform team owns one vetted tool surface, and any agent
consumes it with a single connection...

Sequential vs. a single mega-prompt

  1. Separation of concerns — each agent has one job and one instruction to tune.
  2. Quality compounds — the editor fixes what the drafter missed; the packager never has to write prose.
  3. Swappable stages — drop in a "Legal Review" agent without touching the others.
🏢
Pipelines model real processes
Intake → enrich → validate → route is the shape of countless business processes. Sequential workflows let you express that directly, with an agent per step you can test, observe, and improve independently. When steps are independent instead of dependent, reach for concurrent workflows to run them in parallel.
