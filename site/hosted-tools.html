Hosted Tools

Function tools run your Python. Hosted tools run on the model provider's side — a sandboxed code interpreter and a web search the model invokes itself, no infrastructure from you. You'll build the Vesper Research Desk: an equity-research assistant that searches live sources and runs real arithmetic instead of hallucinating numbers.

Hosted tools need no servers from you — the provider executes them and returns the result to the agent.

1 · Attach hosted tools

Both tools are plain classes from agent_framework. Construct them and pass them in the agent's tools=[...] list, exactly like function tools.

main.py
import asyncio
from agent_framework import HostedCodeInterpreterTool, HostedWebSearchTool
from agent_framework.azure import AzureOpenAIChatClient


async def main() -> None:
    agent = AzureOpenAIChatClient().create_agent(
        name="Vesper-Research",
        instructions=(
            "You are an equity research analyst. Use web search for current facts "
            "and the code interpreter for any calculation. Never estimate numbers "
            "in your head — compute them. Cite the sources you used."
        ),
        tools=[
            HostedWebSearchTool(),
            HostedCodeInterpreterTool(),
        ],
    )

    resp = await agent.run(
        "Contoso reported $4.2B revenue this year vs $3.6B last year. "
        "What is the year-over-year growth rate, and what recent headlines "
        "might explain it?"
    )
    print(resp.text)


if __name__ == "__main__":
    asyncio.run(main())
💡
Provider support varies
Hosted tools depend on the backing service. Azure OpenAI and Foundry expose the code interpreter and web search; some OSS providers don't. If a tool isn't supported, the call raises at run time — check your model's capability matrix.

2 · The model decides when to use them

You don't call the tools — the model does. For the prompt above it will search the web for recent Contoso news and run a small division in the sandbox to get an exact growth rate.

python main.py — research desk
[web_search] "Contoso revenue 2026 earnings"
[code_interpreter] (4.2 - 3.6) / 3.6 * 100  ->  16.6666...
Year-over-year revenue growth is **16.7%** ($3.6B → $4.2B).

Likely drivers from recent coverage:
- Expansion of the cloud security line (reported new enterprise wins)
- A price increase on the flagship subscription tier
- Favorable FX in the EMEA segment

Sources: Contoso FY26 earnings release; two market-news summaries.

Computation you can trust

The difference is subtle but critical: without the code interpreter, "16.7%" is a token the model predicts. With it, the number comes from an actual execution. For anything numeric — finance, units, dates, statistics — hosted code execution turns a plausible guess into a verifiable result.

  1. Web search grounds the answer in current, citable facts.
  2. Code interpreter guarantees the math is correct, not approximated.
  3. The agent stitches both into one grounded, calculated response.
🏢
Hosted vs. local is a governance decision
Hosted tools are fast to adopt but run outside your boundary — prompt content leaves your process. For regulated data, prefer local function tools or a private MCP server you control. Use hosted web search for public research, and keep proprietary calculations in code you own. The next two lessons cover MCP and middleware, your levers for exactly that control.
