Supervisor Agent

Agent-as-tool delegates one bounded sub-task. But some problems need a manager that plans: decompose the goal, pick who works next, track progress, and replan when things stall. That's the Magentic pattern — an LLM-powered supervisor coordinating a team. You'll build the Helix incident war-room, where a supervisor drives a diagnostician, a researcher, and a remediation engineer until a production outage is resolved.

The manager runs the loop

The supervisor maintains a plan and a progress ledger. After each round it decides the next agent, or replans if the team stalls — no hard-coded routing.

1 · Build the specialist team

main.py
import asyncio
from agent_framework import MagenticBuilder
from agent_framework.azure import AzureOpenAIChatClient


async def main() -> None:
    client = AzureOpenAIChatClient()

    diagnostician = client.create_agent(
        name="Diagnostician",
        instructions=(
            "You triage production incidents. Form hypotheses about root cause from "
            "symptoms, logs, and recent deploys. State the single most likely cause."
        ),
    )
    researcher = client.create_agent(
        name="Researcher",
        instructions=(
            "You search runbooks and past incidents for matching signatures and known "
            "mitigations. Cite the runbook step that applies."
        ),
    )
    remediation = client.create_agent(
        name="RemediationEngineer",
        instructions=(
            "You propose a concrete, minimal, reversible fix and the rollback step. "
            "Be specific about commands or config changes."
        ),
    )

2 · Wire the Magentic supervisor

.participants(**agents) registers the team by name. .with_standard_manager(...) attaches the Magentic-One manager (its planning prompts come from the original paper) and sets the inner-loop limits: max_round_count caps total coordination rounds, max_stall_count triggers a replan when progress stops.

main.py (cont.)
    workflow = (
        MagenticBuilder()
        .participants(
            diagnostician=diagnostician,
            researcher=researcher,
            remediation=remediation,
        )
        .with_standard_manager(
            chat_client=client,
            max_round_count=12,
            max_stall_count=3,
            max_reset_count=2,
        )
        .build()
    )

    task = (
        "Checkout is returning HTTP 500 for ~30% of users since the 14:02 deploy. "
        "Find the root cause and propose a safe fix with a rollback plan."
    )

    async for event in workflow.run_stream(task):
        if event.text:
            print(event.text, end="", flush=True)


if __name__ == "__main__":
    asyncio.run(main())

Supervisor vs. the other patterns

PatternWho decides next stepUse when
SequentialYou (fixed order)Steps always run in the same order
HandoffCurrent agentRoute a conversation to its owner
Agent-as-toolCoordinator's model (one call each)Compose bounded sub-tasks
Supervisor (Magentic)Manager, every round + replansOpen-ended goals needing planning
💡
Stalls trigger replanning
If specialists go max_stall_count rounds without progress, the manager rewrites the plan instead of looping forever. max_reset_count caps how many times it may start over — your guardrail against runaway cost.
🏢
Add a human to the plan
For high-stakes work, call .with_plan_review(enable=True) so a human approves or revises the manager's plan before any specialist runs, or .with_human_input_on_stall() to step in when the team is stuck. These emit MagenticHumanInterventionRequest events — the same approval mechanics you'll wire up in Human in the Loop.
