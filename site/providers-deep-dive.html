Provider B — Microsoft Foundry

Foundry uses AzureAIAgentClient with an async credential. Note the async with credential scope.

modules/03_providers_deep_dive/azure_ai_provider.py
from agent_framework.azure import AzureAIAgentClient
from azure.identity.aio import AzureCliCredential


async def main() -> None:
    async with AzureCliCredential() as credential:
        client = AzureAIAgentClient(async_credential=credential)
        agent = client.create_agent(
            name="TriageAgent",
            instructions=TRIAGE_INSTRUCTIONS,
        )
        response = await agent.run(
            "User reports an email asking for their password from 'IT Helpdesk'."
        )
        print(response.text)

Choosing authentication

  1. API key — quickest to start; fine for local dev. Keep it in env vars, never in code.
  2. AzureCliCredential — keyless via your az login session; great for development.
  3. DefaultAzureCredential — production default; tries managed identity, env, CLI, and more in order.
🏢
Prefer keyless in production
Managed identity via DefaultAzureCredential removes secrets from your deployment entirely. Reserve API keys for local experiments.
⚠️
Match the credential to the client
Foundry's AzureAIAgentClient expects an async credential (azure.identity.aio) and an async with scope so the token provider closes cleanly.
