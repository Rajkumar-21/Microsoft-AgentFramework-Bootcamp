Declarative Agents

Everything so far has been Python. But agent configuration — instructions, model, the shape of a workflow — is data, not logic. Agent Framework lets you describe it in YAML and load it at runtime. Product managers tweak prompts, ops version the files in Git, and nobody redeploys code. You'll define the Beacon content pipeline declaratively: an agent in YAML, then a whole workflow in YAML.

Factories turn declarative YAML into the same objects you'd build by hand — so declarative and programmatic agents interoperate freely.

1 · Define an agent in YAML

An agent spec uses kind: Prompt with name, instructions, description, and a model block. Values prefixed with =Env. resolve from environment variables at load time.

agent-config.yaml
kind: Prompt
name: Researcher
displayName: Beacon Researcher
description: Gathers and verifies facts on a given topic.
instructions: >
  You research a topic and return 5 verified, sourced facts.
  Be precise; flag anything you cannot confirm.

model:
  id: =Env.AZURE_OPENAI_MODEL
  connection:
    kind: remote
    endpoint: =Env.FOUNDRY_PROJECT_ENDPOINT

Install the package and load it with AgentFactory:

load_agent.py
# pip install agent-framework-declarative agent-framework-foundry --pre
import asyncio
from pathlib import Path
from agent_framework.declarative import AgentFactory
from azure.identity.aio import AzureCliCredential


async def main() -> None:
    yaml_path = Path(__file__).parent / "agent-config.yaml"
    async with (
        AzureCliCredential() as credential,
        AgentFactory(client_kwargs={"credential": credential})
            .create_agent_from_yaml_path(yaml_path) as agent,
    ):
        response = await agent.run("Research: undersea data centers.")
        print(response.text)


if __name__ == "__main__":
    asyncio.run(main())

2 · Define the whole pipeline in YAML

A workflow spec has name, optional inputs, and a list of actions. Here a sequential pipeline invokes three registered agents.

content-pipeline.yaml
name: beacon-content-pipeline
description: Research, write, and edit an article on a topic.

inputs:
  topic:
    type: string
    description: The subject to write about.

actions:
  - kind: InvokeAgent
    id: research
    displayName: Research the topic
    agent: ResearcherAgent
    input: =Workflow.Inputs.topic
    output: Local.facts

  - kind: InvokeAgent
    id: write
    displayName: Draft the article
    agent: WriterAgent
    input: =Local.facts
    output: Local.draft

  - kind: InvokeAgent
    id: edit
    displayName: Polish for publication
    agent: EditorAgent
    input: =Local.draft

Register your agents by the names the YAML references, then build and run:

run_pipeline.py
from agent_framework.declarative import WorkflowFactory

factory = WorkflowFactory()
factory.register_agent("ResearcherAgent", researcher_agent)
factory.register_agent("WriterAgent", writer_agent)
factory.register_agent("EditorAgent", editor_agent)

workflow = factory.create_workflow_from_yaml_path("content-pipeline.yaml")
result = await workflow.run({"topic": "undersea data centers"})
print(result)

Declarative vs. programmatic

Use declarative when…Use programmatic when…
Standard orchestration patternsComplex custom control flow
Config changes frequentlyTight integration with existing Python
Non-developers edit the flowYou need maximum flexibility
⚠️
Python 3.10–3.13 only
The declarative engine uses Power Fx for its =Expr expressions, which doesn't yet support Python 3.14. Pin a supported interpreter for declarative projects.
🏢
Centralize agent definitions
Store agent and workflow YAML in Azure App Configuration (azure-appconfiguration-provider + AgentFactory + DefaultAzureCredential). Ops updates an instruction in the portal and every instance picks it up — prompts become governed configuration, not redeploys. Declarative YAML can even call MCP tools and HTTP endpoints, bridging to the integrations from MCP Tools.
