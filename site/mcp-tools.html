MCP Tools

The Model Context Protocol (MCP) is an open standard for exposing tools to LLMs over a wire protocol. Instead of writing every tool in your codebase, you connect to an MCP server and its tools appear to your agent automatically. You'll build the Orbit DevOps Assistant: it answers from the live Microsoft Learn MCP server and a local repository MCP — one agent, many tool servers.

1 · Connect a remote MCP server

MCP tools are async context managers — they open the connection, discover tools, and clean up on exit. Construct inside async with and pass into tools=[...].

main.py
import asyncio
from agent_framework import MCPStreamableHTTPTool
from agent_framework.azure import AzureOpenAIChatClient


async def main() -> None:
    async with MCPStreamableHTTPTool(
        name="MSLearn",
        url="https://learn.microsoft.com/api/mcp",
    ) as learn_docs:
        agent = AzureOpenAIChatClient().create_agent(
            name="Orbit-DevOps",
            instructions=(
                "You are a DevOps assistant. When asked about Azure or Microsoft "
                "tooling, search the Microsoft Learn MCP server and answer from the "
                "retrieved docs. Quote the exact guidance and link the source."
            ),
            tools=[learn_docs],
        )

        resp = await agent.run(
            "What's the recommended way to pass secrets to an Azure Container App? "
            "Cite the docs."
        )
        print(resp.text)


if __name__ == "__main__":
    asyncio.run(main())

2 · Add a local stdio server

Local MCP servers launch as subprocesses. Here a filesystem server lets the agent read files in your repo — combine it with the docs server for a "search the docs and check our code" assistant.

local + remote
from agent_framework import MCPStdioTool, MCPStreamableHTTPTool

async with (
    MCPStreamableHTTPTool(name="MSLearn", url="https://learn.microsoft.com/api/mcp") as docs,
    MCPStdioTool(
        name="Repo",
        command="npx",
        args=["-y", "@modelcontextprotocol/server-filesystem", "."],
    ) as repo,
):
    agent = AzureOpenAIChatClient().create_agent(
        name="Orbit-DevOps",
        instructions="Use Repo to read our code and MSLearn for official guidance.",
        tools=[docs, repo],
    )
    resp = await agent.run("Does our bicep match the docs' secret-handling guidance?")
    print(resp.text)
⚠️
Third-party servers are third-party code
Connecting to a non-Microsoft MCP server sends prompt content to that provider and runs tools Microsoft hasn't vetted. Prefer servers hosted by trusted providers, review what data is shared, and log tool calls for audit. Pass secrets only via per-run headers — never bake them into a shared client.

The recommended approach is to store secrets at the Container App level and
reference them from environment variables, or—better for production—reference
them from Azure Key Vault using a managed identity so no secret value is stored
in the app definition.

🏢
MCP is how agents scale past one codebase
As tools multiply, you don't want them all in one app. MCP lets platform teams publish tool servers (a payments server, a ticketing server, a docs server) that any agent can consume with a URL. You'll see this federation pattern again in the Remote tools via MCP architecture and the capstone gateway.
