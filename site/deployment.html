Deployment

A great agent on your laptop helps no one. Production means a hosted endpoint, scaling, durability, and an invocation contract clients can rely on. Agent Framework gives you several hosting surfaces — and for serverless, stateful agents, the Azure Functions Durable Extension is the sweet spot. You'll deploy the Atlas support agent to Azure Functions and call it over HTTP.

1 · Register the agent with a Function App

Install the Azure Functions extra and wrap your agent in AgentFunctionApp. It generates the HTTP trigger and wires in the Durable Extension so long-running runs survive process recycling.

function_app.py
# pip install agent-framework-azurefunctions --pre
from agent_framework.azure import AgentFunctionApp
from agent_framework.foundry import FoundryChatClient

agent = FoundryChatClient().create_agent(
    name="Atlas",
    instructions="You are Atlas, a customer support agent. Be concise and helpful.",
)

# Exposes POST /api/agents/Atlas/run, backed by the Durable Extension.
app = AgentFunctionApp(agents=[agent])

3 · Ship to Azure

Deploy with the Azure Functions tooling (or azd). The same endpoint runs in the cloud, scales on demand, and — because it's the Durable Extension — can pause for approvals or long tool calls without holding a process open.

deploy
func azure functionapp publish atlas-support-prod
Deployment successful.
  Atlas_run: https://atlas-support-prod.azurewebsites.net/api/agents/Atlas/run
💡
Wire observability before you scale
Add configure_azure_monitor() from Observability to your Function App's startup so every production run emits traces and token metrics to Application Insights from day one.
⚠️
Use managed identity, not keys
In production, authenticate the Function App to your model with a ManagedIdentityCredential rather than embedding API keys. It removes secret rotation and avoids the credential-probing pitfalls of DefaultAzureCredential at scale.
🏢
Durable = resilient by default
The Durable Extension checkpoints workflow state, so a multi-step agent run resumes exactly where it left off after a deploy, crash, or scale event — the production backbone for the system you'll assemble in the Capstone.
