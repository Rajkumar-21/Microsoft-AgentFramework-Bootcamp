Conversation Threads

Real conversations build on what came before. You'll build the Summit Bank Mortgage Pre-Qualification Advisor — an agent that interviews an applicant across several turns and remembers every detail — then run the same questions without a thread to watch it forget everything.

What a thread is

A thread is the conversation's memory. Create one, then pass it to every run call so each turn sees the full history.

With a shared thread, turn 4 can see turns 1–3. Without it, every turn starts blank.

Create and use a thread

The thread factory is synchronous — no await. The runs are async, and you pass thread=thread to each.

  1. Create the agent once.
  2. Call thread = agent.get_new_thread() — synchronous, returns a fresh thread.
  3. Pass thread=thread to every await agent.run(...) to carry context forward.
threaded run
agent = client.create_agent(name="MortgageAdvisor", instructions=ADVISOR_INSTRUCTIONS)

thread = agent.get_new_thread()  # sync — no await
for message in TURNS:
    response = await agent.run(message, thread=thread)
    print(response.text)
⚠️
get_new_thread() is sync — don't await it
A common first bug: await agent.get_new_thread(). The thread factory returns the thread directly. Only run(...) and run_stream(...) are awaitable.

Where threads live in production
In-process threads are perfect for a single request. For chat apps that span sessions, persist the conversation (database, cache) and rehydrate it — you'll see durable memory and context providers in the Memory & Context lesson later in the bootcamp.

Mental model

  1. One thread = one conversation. Different users → different threads.
  2. Pass it every turn. Forgetting thread= silently makes the agent amnesiac.
  3. Threads are cheap. Create a new one whenever you want a clean slate.
