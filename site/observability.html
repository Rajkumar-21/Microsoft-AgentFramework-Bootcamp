Observability

You can't operate what you can't see. When an agent loops, stalls, or burns tokens, you need traces, logs, and metrics. Agent Framework emits standard OpenTelemetry GenAI telemetry out of the box — one call wires it up. You'll instrument the Pulse support desk, watch every agent + tool span live in the Aspire Dashboard, then ship the same signals to Azure Monitor.

Because the framework speaks OTLP, the same instrumentation feeds a local dashboard in dev and your enterprise APM in prod — no code change.

1 · Turn on telemetry

Install the observability extra, then call configure_otel_providers() once at startup. Set ENABLE_CONSOLE_EXPORTERS=true to print spans to your terminal while developing.

install
pip install agent-framework --pre
# console output while developing
export ENABLE_CONSOLE_EXPORTERS=true
main.py
import asyncio
from typing import Annotated
from pydantic import Field
from agent_framework import tool
from agent_framework.azure import AzureOpenAIChatClient
from agent_framework.observability import configure_otel_providers


@tool
def lookup_order(order_id: Annotated[str, Field(description="Order ID")]) -> str:
    """Look up an order's status."""
    return f"Order {order_id}: shipped, arriving Thursday."


async def main() -> None:
    configure_otel_providers()  # traces + logs + GenAI metrics

    client = AzureOpenAIChatClient()
    pulse = client.create_agent(
        name="Pulse",
        instructions="You are a support agent. Use tools to answer order questions.",
        tools=[lookup_order],
    )

    reply = await pulse.run("Where is order A-7781?")
    print(reply.text)


if __name__ == "__main__":
    asyncio.run(main())

2 · View traces live in the Aspire Dashboard

The .NET Aspire Dashboard is a zero-config OTLP viewer — perfect for local development. Run it in Docker and point your app's OTLP endpoint at it.

aspire dashboard
docker run --rm -it -p 18888:18888 -p 4317:18889 \
  mcr.microsoft.com/dotnet/aspire-dashboard:latest
# then tell the app where to send OTLP
export OTLP_ENDPOINT=http://localhost:4317
Dashboard → http://localhost:18888  (traces, structured logs, metrics)

Open the dashboard and you'll see one trace per run, with nested spans: the agent invocation, the chat-completion call (with token counts), and each tool call — all following the OpenTelemetry GenAI semantic conventions.

3 · Ship to Azure Monitor in production

Same instrumentation, enterprise backend. Install the Azure Monitor distro and the framework routes its OTLP stream to Application Insights.

azure_monitor.py
# pip install azure-monitor-opentelemetry
from azure.monitor.opentelemetry import configure_azure_monitor
from agent_framework.observability import configure_otel_providers

# Reads APPLICATIONINSIGHTS_CONNECTION_STRING from the environment
configure_azure_monitor()
configure_otel_providers()
# Agent traces now flow into Application Insights → end-to-end transaction view
💡
Prefer standard OTEL_* env vars
Instead of hard-coding endpoints, set the standard OTEL_EXPORTER_OTLP_ENDPOINT, OTEL_SERVICE_NAME, and related variables. The framework honors them, so the same build runs against any collector in any environment.
⚠️
Sensitive data is off by default
Prompt and response contents are not captured unless you opt in (e.g. enable_instrumentation(enable_sensitive_data=True)). Keep it off in production unless your logging store is approved for that data.
🏢
Debug visually with DevUI
During development, serve(entities=[pulse], tracing_enabled=True) launches a local web UI where you chat with the agent and inspect each trace inline — invaluable before you wire up the production pipeline you'll deploy in Deployment.
