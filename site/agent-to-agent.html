Agent-to-Agent (A2A)

Until now every agent lived in one process. A2A is an open protocol for agents to talk across processes, teams, and organizations over HTTP/JSON-RPC. A remote agent advertises its skills through an agent card; you call it like a local one. You'll build the Nexus partner network: connect to a partner's shipping agent, federate it as a tool, and expose your own agent as an A2A server.

Each agent publishes a card at a well-known URL describing its skills. Clients discover and invoke it without sharing code or models.

1 · Call a remote agent

Install the A2A extra, then open an A2AAgent pointed at the partner's URL. It fetches the agent card and behaves like any local agent — run(), streaming, threads.

client.py
# pip install agent-framework-a2a --pre
import asyncio
from agent_framework.a2a import A2AAgent


async def main() -> None:
    async with A2AAgent(
        name="shipping_partner",
        url="https://partners.example.com/agents/shipping",
    ) as shipping:
        response = await shipping.run("ETA for tracking 1Z-88R to 60601?")
        print(response.messages[0].text)


if __name__ == "__main__":
    asyncio.run(main())

2 · Federate the remote agent as a tool

A remote agent is still an agent — so .as_tool() works. Drop the partner's capability straight into your local concierge's toolset; the model calls it like any function.

concierge.py
from agent_framework.azure import AzureOpenAIChatClient
from agent_framework.a2a import A2AAgent

async def build_concierge():
    shipping = A2AAgent(name="shipping", url="https://partners.example.com/agents/shipping")

    concierge = AzureOpenAIChatClient().create_agent(
        name="NexusConcierge",
        instructions="Help customers. For delivery questions, use the shipping tool.",
        tools=[
            shipping.as_tool(
                name="track_shipment",
                description="Get delivery status/ETA for a tracking number.",
                arg_name="question",
            ),
        ],
    )
    return concierge

3 · Expose your own agent over A2A

Wrap any agent in an A2AExecutor and host it with the a2a-sdk as a Starlette (ASGI) app. The framework serves the agent card at the well-known path so partners can discover it.

server.py
from agent_framework.a2a import A2AExecutor
from agent_framework.azure import AzureOpenAIChatClient

agent = AzureOpenAIChatClient().create_agent(
    name="CatalogAgent",
    instructions="Answer questions about our product catalog and pricing.",
)

# A2AExecutor adapts the agent to the A2A server interface.
executor = A2AExecutor(agent)
# Host `executor` with the a2a-sdk (Starlette/ASGI). It publishes:
#   GET /.well-known/agent-card.json   → discovery
#   POST /                              → JSON-RPC invocation
partner discovers your agent
curl https://you.example.com/.well-known/agent-card.json

💡
Discovery without code sharing
You only need the partner's URL. An A2ACardResolver reads the /.well-known/agent-card.json to learn the agent's skills at runtime — versioned, language-agnostic contracts instead of shared libraries.
🏢
A2A is one hosting surface among several
A2A is ideal for cross-org federation, but it's not the only way to expose an agent. You can also publish OpenAI-compatible endpoints, run on Azure Functions for long-running jobs, or serve a web UI — the full menu you'll work through in Deployment.
