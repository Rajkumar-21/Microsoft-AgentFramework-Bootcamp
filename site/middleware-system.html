Middleware

Cross-cutting concerns — logging, security, redaction, caching — shouldn't live inside your agent logic. Middleware wraps execution so you can inspect and modify inputs, outputs, and control flow from the outside. You'll build the Aegis compliance layer: it audits every run, redacts PII before it reaches the model, and blocks a sensitive tool unless a condition is met.

1 · Audit every run (agent middleware)

Function-based middleware is just an async function taking the context and a call_next callback. Mutate the context, then await call_next().

audit_middleware.py
import time
from collections.abc import Awaitable, Callable
from agent_framework import AgentRunContext


async def audit_run(
    context: AgentRunContext,
    call_next: Callable[[], Awaitable[None]],
) -> None:
    """Log every agent run with timing — the Aegis audit trail."""
    started = time.perf_counter()
    print(f"[audit] run started")
    await call_next()
    elapsed = (time.perf_counter() - started) * 1000
    print(f"[audit] run completed in {elapsed:.0f} ms")

2 · Redact PII (chat middleware)

Chat middleware sees the raw messages headed to the model. Here we scrub anything that looks like a Social Security number before it ever leaves the process.

redact_middleware.py
import re
from collections.abc import Awaitable, Callable
from agent_framework import ChatContext

SSN = re.compile(r"\b\d{3}-\d{2}-\d{4}\b")


async def redact_pii(
    context: ChatContext,
    call_next: Callable[[], Awaitable[None]],
) -> None:
    """Mask SSNs in outbound messages before the model sees them."""
    for message in context.messages:
        if message.text:
            message.text = SSN.sub("[REDACTED-SSN]", message.text)
    await call_next()

3 · Gate a sensitive tool (function middleware)

Function middleware can block a call entirely. Set context.result and context.terminate = True to short-circuit without running the tool.

guard_middleware.py
from collections.abc import Awaitable, Callable
from agent_framework import FunctionMiddleware, FunctionInvocationContext


class ApprovalGuard(FunctionMiddleware):
    """Block issue_refund over $500 unless approved=True was supplied."""

    async def process(
        self,
        context: FunctionInvocationContext,
        call_next: Callable[[], Awaitable[None]],
    ) -> None:
        if context.function.name == "issue_refund":
            amount = float(context.arguments.get("amount", 0))
            if amount > 500 and not context.arguments.get("approved"):
                context.result = "BLOCKED: refunds over $500 require approval."
                context.terminate = True
                print(f"[guard] blocked ${amount:.2f} refund — needs approval")
                return
        await call_next()

4 · Register the layers

Pass middleware when creating the agent. Agent-level middleware wraps run-level middleware.

main.py
agent = AzureOpenAIChatClient().create_agent(
    name="Aegis-Support",
    instructions="You are a support agent. Use issue_refund for refunds.",
    tools=[issue_refund],
    middleware=[audit_run, redact_pii, ApprovalGuard()],
)

resp = await agent.run("Refund order 8842 for $750, customer SSN 123-45-6789.")
print(resp.text)

💡
Function-based or class-based
Use a plain async def for stateless concerns (logging, redaction). Subclass FunctionMiddleware/AgentMiddleware when you need state — a cache, a counter, an injected client.
🏢
Middleware is where compliance lives
Auditing, PII handling, rate limiting, cost caps, and approval gates are policy — they belong in a reusable layer, not scattered through prompts. Build them once as middleware and apply them to every agent in your fleet. This is the production-hardening you'll formalize in the architecture track.
