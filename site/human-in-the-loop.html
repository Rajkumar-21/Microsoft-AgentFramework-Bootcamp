Human in the Loop

Autonomy is great — until an agent is about to move money, delete data, or email a customer. For those moments you want a checkpoint a human must clear. Agent Framework workflows pause on @tool(approval_mode="always_require"), emit a request, and wait. You'll build the Sentinel payments desk: an agent that must get human sign-off before executing a wire transfer, then resumes with the decision.

The workflow suspends at the tool call and emits a request_info event. Nothing executes until you send a response keyed by the request id.

1 · Mark the sensitive tool for approval

approval_mode="always_require" tells the framework: never run this tool without explicit human sign-off. No extra builder config is needed — SequentialBuilder handles the pause.

main.py
import asyncio
from typing import Annotated
from pydantic import Field
from agent_framework import SequentialBuilder, tool
from agent_framework.azure import AzureOpenAIChatClient


@tool(approval_mode="always_require")
def execute_wire(
    payee: Annotated[str, Field(description="Beneficiary name")],
    amount_usd: Annotated[float, Field(description="Amount in USD")],
) -> str:
    """Execute a wire transfer. Requires human approval before running."""
    return f"WIRE SENT: ${amount_usd:,.2f} to {payee} (ref TXN-90421)."


async def main() -> None:
    client = AzureOpenAIChatClient()

    payments_agent = client.create_agent(
        name="PaymentsAgent",
        instructions=(
            "You process vendor payments. When asked to pay, call execute_wire with "
            "the payee and amount. Confirm the result to the user."
        ),
        tools=[execute_wire],
    )

    workflow = SequentialBuilder(participants=[payments_agent]).build()

2 · Catch the request, decide, resume

Run with stream=True. When an event's type == "request_info", the payload (event.data) is a Content with type == "function_approval_request". Build a response with to_function_approval_response(approved=...) and feed it back via responses={request_id: ...}. Runs aren't isolated — state carries across calls.

main.py (cont.)
    async def pump(stream) -> dict | None:
        """Collect approval requests; print any agent output."""
        responses: dict = {}
        async for event in stream:
            if event.type == "request_info":
                req = event.data  # Content, type == "function_approval_request"
                fc = req.function_call
                # In a real app: route to a reviewer UI / queue. Here: simple policy.
                approved = fc.arguments.get("amount_usd", 0) <= 50_000
                print(f"[approval] {fc.name}({fc.arguments}) -> approved={approved}")
                responses[event.request_id] = req.to_function_approval_response(approved=approved)
            elif getattr(event, "text", None):
                print(event.text, end="", flush=True)
        return responses or None

    stream = workflow.run("Pay vendor Northwind Supplies $48,000.", stream=True)
    pending = await pump(stream)
    while pending is not None:
        stream = workflow.run(stream=True, responses=pending)
        pending = await pump(stream)


if __name__ == "__main__":
    asyncio.run(main())

⚠️
A denial is not an error
When approved=False, the tool is skipped and the agent continues with that knowledge — it doesn't crash. Make sure your instructions tell the agent how to respond gracefully to a declined action.
🏢
Durable approvals across restarts
In production a human may take hours to approve. Pass checkpoint_storage= to the builder: pending requests are saved with the checkpoint, so the process can exit and a later run re-emits the request_info event to be answered. Combine with memory & persistence for fully resumable workflows.
