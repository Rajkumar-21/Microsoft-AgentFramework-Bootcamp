Ops Copilot

Ops Copilot is an incident-response agent for SRE / operations teams — one deployable Azure Functions service that combines many lessons: function tools, MCP tools discovered from the registry, middleware for audit and PII redaction, a Magentic supervisor, human-in-the-loop approvals, memory, and observability.

📁
Where it lives
Source: projects/ops-copilot/. It connects to the Agent Registry to discover MCP servers and to self-register.

An alert is planned by the supervisor, which coordinates triage, mitigation (gated by human approval), and comms — pulling MCP tools from the registry and emitting traces to Azure Monitor.

1 · Tools, with a human gate on risky actions

Read-only tools run freely; the production action is marked approval_mode="always_require", so the framework pauses for a human before it executes.

app/tools.py
from typing import Annotated
from pydantic import Field
from agent_framework import tool

@tool
def get_metric(host: Annotated[str, Field(description="Host or service.")],
               metric: Annotated[str, Field(description="Metric, e.g. cpu.")]) -> str:
    """Return the latest value for a host metric."""
    ...

@tool(approval_mode="always_require")
def restart_service(host: Annotated[str, Field(description="Host to restart.")],
                    service: Annotated[str, Field(description="Service name.")]) -> str:
    """Restart a production service. Requires human approval before running."""
    return f"Service '{service}' on '{host}' was restarted."

2 · Specialists with audit middleware + registry MCP tools

app/agents.py
from agent_framework import ChatMessageStore
from agent_framework.azure import AzureOpenAIChatClient
from .middleware import audit_middleware       # audit + PII redaction (Lesson 10)
from .registry import discover_mcp_tools        # pull approved MCP servers
from .tools import get_metric, lookup_runbook, restart_service

client = AzureOpenAIChatClient()
mcp_tools = await discover_mcp_tools(tag="operations")

mitigation = client.create_agent(
    name="Mitigation",
    instructions="Propose then, after approval, execute the least disruptive fix.",
    tools=[restart_service, *mcp_tools],
    middleware=[audit_middleware],
    chat_message_store_factory=ChatMessageStore,   # remember the timeline (Lesson 18)
)

3 · A Magentic supervisor ties them together

app/workflow.py
from agent_framework import MagenticBuilder

workflow = (
    MagenticBuilder()
    .participants(triage=triage, mitigation=mitigation, comms=comms)
    .with_standard_manager(chat_client=client, max_round_count=12,
                           max_stall_count=3, max_reset_count=1)
    .build()
)

4 · Deploy as one durable endpoint

function_app.py
from agent_framework.azure import AgentFunctionApp
from .workflow import build_incident_workflow

ops_copilot = build_incident_workflow().as_agent(name="OpsCopilot")
app = AgentFunctionApp(agents=[ops_copilot])
# POST /api/agents/OpsCopilot/run
run & deploy

Production notes
Use managed identity for Azure OpenAI and the registry (no keys), set APPLICATIONINSIGHTS_CONNECTION_STRING so traces flow to Azure Monitor, and keep the approval gate on every irreversible tool. Compare with the customer-facing Commerce Concierge.
