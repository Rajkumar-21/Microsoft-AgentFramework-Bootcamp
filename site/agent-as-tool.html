Agent as Tool

The simplest way to compose agents is to make one agent a tool of another. as_tool() wraps any agent in an AIFunction, so a coordinator can call specialists exactly like it calls a Python function — the model decides which one and when. You'll build the Atlas travel concierge: one front-desk agent that delegates to flight, hotel, and weather specialists.

Each specialist is a self-contained agent exposed as a function. The concierge sees only their final text — full context isolation.

1 · Build the specialist agents

Specialists are ordinary agents. Give each a tight, single responsibility and (optionally) its own function tools. Here the flight and hotel specialists carry mock lookup tools.

main.py
import asyncio
from typing import Annotated
from pydantic import Field
from agent_framework.azure import AzureOpenAIChatClient


def search_flights(
    origin: Annotated[str, Field(description="Departure city/airport")],
    destination: Annotated[str, Field(description="Arrival city/airport")],
) -> str:
    """Return mock flight options for a route."""
    return f"{origin}->{destination}: AT204 $480 (nonstop, 7h15m), AT118 $410 (1 stop)."


def search_hotels(
    city: Annotated[str, Field(description="City to stay in")],
    nights: Annotated[int, Field(description="Number of nights")],
) -> str:
    """Return mock hotel options for a city."""
    return f"{city} x{nights}n: The Mariner $190/n (4.6*), Ceylon Suites $250/n (4.8*)."


async def main() -> None:
    client = AzureOpenAIChatClient()

    flight_agent = client.create_agent(
        name="FlightSpecialist",
        instructions="You find flights. Always call search_flights, then summarize the best 2 options.",
        tools=[search_flights],
    )
    hotel_agent = client.create_agent(
        name="HotelSpecialist",
        instructions="You find hotels. Always call search_hotels, then recommend one with a reason.",
        tools=[search_hotels],
    )
    weather_agent = client.create_agent(
        name="WeatherSpecialist",
        instructions="Give a short, seasonal packing-relevant weather outlook for the destination.",
    )

2 · Wrap each specialist with as_tool()

as_tool() returns an AIFunction. The name and description are what the coordinator's model reads to decide routing — write them like you'd write a tool docstring. arg_name controls the single string argument the coordinator passes (default "task").

main.py (cont.)
    concierge = client.create_agent(
        name="AtlasConcierge",
        instructions=(
            "You are a travel concierge. Use the flight, hotel, and weather tools to "
            "assemble a complete trip plan. Call each specialist as needed, then write "
            "one friendly itinerary that combines their answers."
        ),
        tools=[
            flight_agent.as_tool(
                name="get_flights",
                description="Find flight options. Input: origin, destination, and dates.",
                arg_name="request",
            ),
            hotel_agent.as_tool(
                name="get_hotels",
                description="Find hotel options. Input: city and number of nights.",
                arg_name="request",
            ),
            weather_agent.as_tool(
                name="get_weather",
                description="Get a seasonal weather outlook for a destination.",
                arg_name="request",
            ),
        ],
    )

    resp = await concierge.run(
        "Plan a 4-night trip from Boston to Colombo in March — flights, a hotel, "
        "and what to pack."
    )
    print(resp.text)


if __name__ == "__main__":
    asyncio.run(main())

How it differs from a handoff

AspectAgent-as-toolHandoff workflow
ControlCoordinator stays in charge; specialists return and control comes backControl is transferred to the next agent
ContextIsolated — specialist sees only the task stringShared conversation moves with the handoff
Best forDelegating a bounded sub-task and composing resultsRouting a whole conversation to the right owner
💡
Descriptions are the routing logic
There is no router code — the coordinator's model picks tools purely from their name and description. Vague descriptions cause wrong or skipped calls. Treat them like API contracts.
🏢
Stateless by design
Each as_tool() invocation is a fresh run, so specialists don't accumulate state between calls — safe to fan out and reuse across requests. When you need a manager that plans, critiques, and iterates over specialists rather than just calling them once, graduate to the supervisor pattern.
