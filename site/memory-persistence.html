Memory & Persistence

By default an agent forgets everything when the process ends. Production assistants can't. Agent Framework gives you two distinct memory layers: thread persistence (serialize the running conversation so it survives restarts) and context providers (inject durable, cross-session knowledge before each turn). You'll build the Aurora concierge, which recognizes a returning customer and recalls their preferences.

The thread is this conversation's history; the context provider is everything we know about the user, fetched fresh each turn.

1 · Persist the conversation thread

Attach a ChatMessageStore via chat_message_store_factory. After a turn, thread.serialize() returns a plain dict you can save anywhere; later, agent.deserialize_thread(state) restores it.

main.py
import asyncio
import json
from agent_framework import ChatMessageStore
from agent_framework.azure import AzureOpenAIChatClient


async def main() -> None:
    client = AzureOpenAIChatClient()

    aurora = client.create_agent(
        name="Aurora",
        instructions="You are Aurora, a warm hotel concierge. Be concise and personal.",
        chat_message_store_factory=ChatMessageStore,
    )

    # --- session 1 ---
    thread = await aurora.get_new_thread()
    await aurora.run("Hi, I'm Mara. I always take a high floor, away from elevators.",
                     thread=thread)

    state = await thread.serialize()
    with open("mara_thread.json", "w") as f:
        json.dump(state, f)  # persist between sessions
main.py (cont.) — session 2, later
    # --- session 2 (new process / much later) ---
    with open("mara_thread.json") as f:
        saved = json.load(f)

    thread = await aurora.deserialize_thread(saved)   # history restored
    reply = await aurora.run("It's Mara again — book me a room for Friday.",
                             thread=thread)
    print(reply.text)
    # → "Welcome back, Mara! I've reserved a high floor away from the elevators..."


if __name__ == "__main__":
    asyncio.run(main())

2 · Inject long-term memory with a ContextProvider

Thread history is per-conversation. For knowledge that spans every conversation — a loyalty tier, dietary needs, past complaints — implement a ContextProvider. Its invoking() hook runs before each turn and returns a Context whose instructions are merged into the prompt.

memory.py
from collections.abc import Sequence
from agent_framework import ChatMessage, Context, ContextProvider


class CustomerMemory(ContextProvider):
    """Loads durable customer facts from your CRM each turn."""

    def __init__(self, crm: dict[str, str]):
        self._crm = crm

    async def invoking(
        self, messages: Sequence[ChatMessage], **kwargs
    ) -> Context:
        prefs = self._crm.get("preferences", "No profile on file.")
        return Context(
            instructions=f"Known facts about this guest: {prefs}"
        )

Pass it via context_provider= (a single provider — see the note below):

main.py — wiring memory in
    crm = {"preferences": "Gold tier; gluten-free; prefers late checkout."}

    aurora = client.create_agent(
        name="Aurora",
        instructions="You are Aurora, a warm hotel concierge.",
        chat_message_store_factory=ChatMessageStore,
        context_provider=CustomerMemory(crm),
    )

    reply = await aurora.run("Any dining tips for tonight?")
    print(reply.text)
    # → "Since you're gluten-free, I'd suggest our seafood grill — fully GF menu..."

⚠️
Breaking change: context_provider is singular
Recent Python builds replaced the plural context_providers=[...] with a single context_provider=, and removed AggregateContextProvider. To combine sources, compose them inside one provider's invoking() method.
🏢
Scale memory with Redis
For real deployments, back your provider with RedisProvider — it supports full-text and optional hybrid vector search, so the agent retrieves only the relevant memories instead of stuffing every fact into the prompt. Persist thread state to the same store and your assistant is fully stateful across regions.
